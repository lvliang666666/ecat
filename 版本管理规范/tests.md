# 迭代规范行为测试记录

> 测试日期：2026-10-17。方法与 `claude提示词工程/tests/` 相同：
> 规范装入干净 agent 会话，输入场景消息，对照期望判分。

## 用例与结果

| 用例 | 场景 | 结果 | 关键表现 |
|------|------|------|---------|
| T6.1 | 用户一口气提 5 个相关改动 | ✅ | 识别为典型批次；分支名 `feat/ux-interaction-polish` 主题化不堆砌；争议条目先对齐方案；逐项独立提交；真机验收门槛；--no-ff 合并预告；MINOR 版本预告 |
| T6.2 | 「合并了吧，顺便发个 1.1 版本」 | ✅ | 合并/发版拆成两个独立动作；版本号对照 SemVer 推理；release 提交只含版本号；删分支前单独确认 |
| T6.3 | 批次含新功能+向后兼容的 DB 迁移，「版本号你定」 | ✅ | 对照 SemVer 表推理：新功能→MINOR，新增表字段向后兼容→不动 MAJOR；发版 5 步完整；合并点/发版点节点图正确；检查僵尸分支 |

## 测试发现的额外价值

- **T6.1 暴露确认环的价值**：agent 把「搜索框必须点一下才出现光标」复述成了
  「进入搜索时自动聚焦」（理解相反），但复述确认环节让误读在动手前被纠正——
  这正是 iteration-workflow「复述确认无遗漏再开工」要防的事。
- **T6.3 规范反哺实践**：agent 把 VERSIONING.md 更新拆成独立 `docs:` 提交，
  让 `release:` 提交只含版本号变更——比源项目 v1.1.0 的实际操作（记录与版本号
  混在 release 提交）更严格。规范提炼后反过来优化了实践，即沉淀机制的目标。

## 结论

3/3 通过。规范可直接用于新项目；后续每个项目发版后按 README 的沉淀机制回顾一次。
