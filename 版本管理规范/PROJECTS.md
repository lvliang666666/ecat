## 登记规则

- **新项目接入时登记**：复制规范进项目后，在清单中加一行
- **每次同步后更新「最后同步」**：记录该副本对齐正本的日期
- **项目废弃时**：备注标注「已归档」，不删行（保留历史）

## 批量同步（交给 agent 执行）

对清单中的每个项目：

1. **读取项目地址**，确认项目存在且含 `版本管理规范/` 副本
2. **diff 报告差异**：`diff -r <正本> <项目>/版本管理规范`
   - 无差异 → 跳过（已是最新）
   - 有差异 → 列出差异文件清单
3. **判断差异来源**：
   - 差异全部是「正本比副本新」→ 直接用正本覆盖副本
   - 副本有正本没有的改动（项目本地改过规范）→ **停下来报告**，
     等用户拍板是采纳本地改动进正本，还是放弃本地改动
4. **覆盖同步**：`cp` 正本文件到项目副本目录
5. **校验**：再次 `diff -r` 确认完全一致
6. **提交**：项目内 `git add 版本管理规范 && git commit -m "docs(spec): 同步规范正本至<日期>版本"`
7. **更新本清单**：该项目的「最后同步」改为当天

> 同步方向永远是：正本 → 项目副本（单向）。
> 项目副本上发现规范要改进的，先改副本验证，再回写正本（见 README 沉淀机制）。
